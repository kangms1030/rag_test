📋 전체 개요 Foundation

📌 chatbot_demo_v2란?

chatbot_demo_v2는 학교 유·무선 네트워크(스쿨넷) 장애상담을 위한 AI 챗봇입니다. LangGraph를 제어구조로 사용하여, 사용자의 질문을 분석하고 적절한 경로(시나리오/FAQ/RAG/웹검색)로 라우팅하여 최적의 답변을 생성합니다.

v1(chatbot_demo)에서 v2로 진화하면서 다음 핵심 기능이 추가되었습니다:

  • 🔄 사이클(CRAG/에스컬레이션) — 첫 시도에서 만족스럽지 않으면 다시 시도
  • 🙋 HITL(Human-In-The-Loop) — 애매한 질문은 사용자에게 되묻기
  • 💬 대화 메모리 — 후속 질문의 맥락을 기억
  • 🧩 서브그래프 — RAG 엔진을 LangGraph 서브그래프로 분해하여 각 단계를 관측 가능
⚡ 핵심 설계 원칙

🎯 결정론 경로 LLM 0회

버튼 클릭(시나리오) 및 FAQ 정확일치 경로는 LLM을 한 번도 호출하지 않습니다. 미리 저장된 답변을 그대로 반환하여 속도와 비용을 모두 절약합니다.

🛡️ LLM 노드 안전 설계

모든 LLM 노드는 .env로 개별 토글 가능하며, 실패 시 예외를 던지지 않고 pass-through(원문 유지)합니다. LLM이 죽어도 챗봇은 동작합니다.

💰 예산(Budget) 제어

CRAG 재검색 1회, 롤백 A/B/C 각 1회, 에스컬레이션 1회 — 모든 사이클에 예산 상한이 있어 무한루프가 구조적으로 불가능합니다.

🔍 관측 가능성

모든 노드가 LangSmith에 개별 run으로 기록됩니다. SSE 스트리밍으로 브라우저에 실시간 진행상황이 표시됩니다.

💡 파이프라인 다이어그램 범례
 파란색 — 결정론 노드 (LLM 0회)
 노란색 — LLM 노드 (토글 가능, 실패 시 pass-through)

🔗 ChatState — 메인그래프 상태 스키마

메인그래프의 상태는 ChatState TypedDict로 정의됩니다. 크게 세 종류의 필드가 있습니다:

종류대표 필드수명
세션 유지session_id, scenario_id, current_node_id, scenario_path, messages체크포인터가 턴 간 보존
입력(per-turn)user_input, input_type, normalized_question, standalone_question매 턴 초기화
결과(per-turn)final_answer, confidence, evidence, composed_answer, grader_verdict매 턴 초기화
💡 핵심: messages 필드 messages: Annotated[list, add_messages] — add_messages 리듀서가 이전 이력에 누적합니다. 절대 매 턴 초기화하지 않습니다. 이것이 대화 메모리의 핵심입니다.

① 입력 처리 단계 결정론

normalize_input LLM 0회 정규화 + HumanMessage 적재

무엇을 하는가?

사용자 입력을 받아 첫 번째로 처리하는 관문입니다. 두 가지 입력 유형을 구분합니다:

📱 버튼 입력 (action)

  • input_type = "action"
  • action_type이 "scenario_option"인지 검증
  • node_id, option_id 필수 확인
  • 정규화 불필요 (정해진 버튼 ID 사용)

⌨️ 자유 입력 (text)

  • input_type = "text"
  • 빈 입력이면 EmptyInputError → HTTP 400
  • normalize_text()로 정규화 (NFKC, 소문자, 공백 정리)
  • HumanMessage(content=raw)를 messages에 추가 (대화 메모리)

핵심 코드 동작

def normalize_input(state: ChatState) -> dict:
    out = new_turn_defaults()          # per-turn 필드 전부 초기화
    out["_turn_started_at"] = time.time()  # 응답 시간 측정 시작

    if input_type == "action":
        # 버튼 입력: node_id/option_id 검증만 수행
        ...
    else:
        raw = state["user_input"].strip()
        out["normalized_question"] = normalize_text(raw)  # NFKC + 소문자 + 공백 정리
        out["messages"] = [HumanMessage(content=raw)]     # 대화 메모리에 추가
    return out
⚠️ new_turn_defaults()의 역할 매 턴 시작 시 per-turn 필드(rag_result, final_answer, confidence 등)를 전부 초기화합니다. 단, messages(대화 메모리)와 scenario_*(시나리오 위치)는 건드리지 않습니다.
▼
load_or_update_session LLM 0회 세션·시나리오 상태 관리

입력 유형에 따라 시나리오 세션 상태를 관리합니다:

  • 자유 입력(text): 이전 시나리오 위치를 중단합니다 (scenario_id=None, current_node_id=None). 자유 입력은 시나리오 트리와 무관한 새로운 질문이기 때문입니다.
  • 버튼 입력(action): 시나리오 상태를 유지합니다. 사용자가 시나리오 트리를 탐색 중이기 때문입니다.
🔑 핵심 원칙 messages(대화 메모리)는 어떤 경우에도 절대 초기화하지 않습니다. 대화 이력이 유지되어야 후속 질문 재작성(contextualize)이 가능합니다.

② 질문 분석 단계 LLM 포함

select_input_kind 라우팅 함수 버튼 / 자유입력 분기

이것은 노드가 아니라 라우팅 함수입니다. LangGraph의 add_conditional_edges에서 사용됩니다.

  • input_type == "action" → scenario_action_handler (버튼 경로)
  • input_type == "text" → contextualize_query (자유입력 경로)
scenario_action_handler LLM 0회

버튼 클릭 시 시나리오 트리에서 다음 노드로 이동합니다.

  • tree.resolve_option(node_id, option_id)로 다음 노드 결정
  • __restart__ 옵션이면 경로 초기화
  • 종단 노드(terminal)면 scenario_completed = True
  • 이동 경로(scenario_path)에 선택한 라벨 추가
contextualize_query LLM 최대 1회

후속 질문을 독립 질문으로 재작성합니다. "그거"를 구체적 대상으로 바꿉니다.

게이트 조건 (모두 만족해야 실행)

  • settings.contextualize_enabled = true
  • 입력이 자유 텍스트
  • 이전 사용자 발화가 1건 이상 (= 후속 질문)

동작

  • 최근 대화 이력 2000자를 추출
  • contextualize.md 프롬프트로 LLM 호출
  • 재작성 결과의 첫 줄만 사용 (모델이 설명을 덧붙이는 것 방어)
  • 실패 시 원문 유지 (pass-through)
예시:
이전 대화: "비밀번호 변경 방법이요?" → "관리자 메뉴에서 변경 가능합니다"
후속 질문: "그거 어디서 해요?"
재작성 결과: "비밀번호 변경은 어디서 하나요?"
▼
scenario_matcher LLM 0회 FAQ 의미 유사도 매칭

정규화된 질문을 236건의 모범 질답(FAQ)과 비교하여 가장 유사한 것을 찾습니다.

매칭 엔진: SemanticScenarioMatcher

  1. 정확 일치 검사 — 정규화된 질문이 FAQ와 완전 일치하면 즉시 반환 (비용 0)
  2. 임베딩 코사인 유사도 — 사전 계산된 FAQ 임베딩 벡터와 질문 벡터의 코사인 거리로 상위 10개 후보 회수
  3. 크로스인코더 리랭킹 — BGE 리랭커로 상위 후보를 재점수하여 최종 순위 결정

매칭 결과 판정

판정조건의미
exact정규화 문자열 완전 일치100% 확신, FAQ 원문 반환
acceptbest ≥ 0.80 AND margin ≥ 0.30유사도 충분 + 1위 확실, FAQ 채택
reject_ambiguousbest ≥ 0.80 BUT margin < 0.30상위 2개 비슷 → 되묻기 후보
reject_low_scorebest < 0.80유사한 FAQ 없음 → RAG
💡 왜 의미 유사도인가? v1의 문자 유사도(fuzz.ratio)로는 한국어 패러프레이즈가 임계 0.90을 절대 못 넘었습니다. 예: "AP를 설치하고 싶어" ↔ "와이파이는 누가 설치하나요" = 0.4167 (문자) vs 0.957 (의미). 골든셋 기준 FAQ 라우트 정확도: 0%(v1) → 100%(v2).

③ 라우팅 결정 핵심 분기점

route_decider LLM 0회 scenario / faq / clarify / rag 4분기

decide_route() 함수가 매칭 결과를 보고 다음 경로를 결정합니다:

경로조건다음 노드LLM 호출 수
scenario 버튼 입력 (시나리오 트리 탐색) scenario_answer 0회
faq 의미 유사도 accept/exact scenario_answer 0~1회 (합성 시)
clarify 후보 2건 모두 ≥ 0.80 + 차이 < 0.30 clarify_node 0회 (사람이 선택)
rag3x 위 조건 모두 불충족 rag3x_answer 2~5회
⚠️ 되묻기(clarify)의 정의 "후보 2건이 둘 다 정답급인데 어느 쪽인지 못 고를 때" — 1위만 높고 2위가 낮으면(후보가 사실상 1건) 되묻기가 성립하지 않아 RAG로 보냅니다.
▼
clarify_node HITL interrupt() 애매·회색지대 → 후보 2개 되묻기

LangGraph의 interrupt()를 사용하여 실행을 일시정지하고 사용자에게 되묻습니다.

동작 과정

  1. 상위 2개 FAQ 후보를 matcher.top_candidates()로 조회
  2. interrupt({"type": "clarify", "candidates": [...]}) 호출 → 실행 중단
  3. 프론트엔드가 후보 버튼을 렌더링하여 사용자에게 표시
  4. 사용자가 선택하면 Command(resume={"choice": faq_id})로 재개
  5. 후보 선택 → route="faq" → scenario_answer로 이동
  6. "해당없음" 선택 → route="rag3x" → rag3x_answer로 이동

도메인 게이트

웹검색 전에 LLM 1회로 "이 질문이 상담봇 범위인가?"를 판정합니다. 잡담·타분야 질문은 웹에서 답하지 않습니다.

  • IN_DOMAIN → Gemini Grounding 호출
  • OUT_OF_DOMAIN / 판정불가 → 직전 답변으로 되돌아가거나 보류

비용 관리

  • 검색 1회당 과금 ($0.014/회)
  • 하루 상한(기본 100회) 초과 시 자동 차단
  • 근거 출처 없는 답변(모델 내부지식만)은 채택하지 않음

⑤ 답변 후처리 단계 품질 보증

compose_answer LLM 1회 근거 종합 · 상담체 재구성 + 숫자 대조 환각가드

FAQ 원문 또는 RAG 초안을 자연스러운 상담 대화체로 재구성합니다.

FAQ 합성 (composer_faq.md)

  • 검증된 모범답변을 상담체로 풀어 씀
  • 사실·수치·연락처 하나도 빠뜨리지 않고 유지
  • 원문에 없는 내용 추가 금지

RAG 합성 (composer_rag.md)

  • 여러 근거를 종합해 하나의 답변 작성
  • [p53] 형식의 출처 표기 포함
  • 근거에 없는 수치 생성 금지

환각 가드 (LLM 0회, 결정론 대조)

합성문에 근거에 없는 숫자/코드가 새로 생겼는지 check_claims_supported()로 대조합니다. 근거 밖 수치가 발견되면 합성을 폐기하고 원문을 유지합니다.

RAG 경로에서는 [p53] 출처 표기를 실제 근거 페이지와 대조하여 없는 쪽번호 표기를 제거합니다.

판정의미후속 동작

  • FAQ 경로 + 예산 남음: → rag3x_answer 에스컬레이션 (1회 제한)
  • RAG 경로 + 웹검색 ON: → web_search_answer
  • 그 외: 경고 문구만 덧붙이고 → final_formatter
⟲ 에스컬레이션 사이클 (FAQ 경로만 · 1회) FAQ 모범답변이 UNRESOLVED일 때, 같은 질문을 RAG로 다시 시도합니다. escalate_budget를 0으로 소진하여 최대 1회만 허용됩니다.
▼
final_formatter LLM 0회 응답 조립 + AIMessage 적재

모든 경로의 결과를 최종 응답으로 조립하는 마지막 노드입니다.

경로별 처리

  • scenario/faq: 합성 답변이 있으면 교체, 없으면 원문 유지
  • rag3x: RAG 결과에서 답변·근거·검증 정보 추출
  • web_search: 웹 답변 + 출처 + 경고 문구 조립

공통 처리

  • AIMessage(content=answer)를 messages에 추가 (대화 메모리)
  • 전체 소요 시간(total_s) 기록
  • LangSmith에 최종 메타데이터 첨부

🔍 prepare — 초기화

시작 시각, 데드라인(240초), CRAG 예산(1), 롤백 예산(각 1)을 설정합니다.

🔍 retrieve — 임베딩 → 청크검색 → 리랭킹

질문을 임베딩하여 ChromaDB/Flat Index에서 관련 청크를 검색하고, BGE 리랭커로 상위 6개 페이지를 선별합니다.

CRAG 재검색 안전가드

재작성 질문으로 다시 검색했을 때, 결과가 더 나쁘면(top score 하락 또는 path=="none") 원본 검색 결과를 유지합니다.

⭐ grade_evidence — 근거 3등급 판정 (2026-07-27 신설)

왜 필요한가?

검색 랭킹만으로는 "AP 설치"라는 표현이 겹친다는 이유로 장애조치표를 1순위로 올리는 실패를 잡을 수 없습니다. 의미 판정만이 유효합니다.

3등급 판정

등급기준컨텍스트 예산
primary이 근거만으로 답할 수 있음페이지 전문 (최대 4000자)
supporting주제는 맞으나 핵심은 없음매칭 청크만 축약 (최대 800자/페이지)
irrelevant질문과 다른 주제제외

예산 배분 핵심

supporting 총예산 = primary 분량의 50% (절대 상한 2000자). 정답 근거가 배경 설명에 묻히지 않게 하는 핵심 장치입니다.

primary가 0개여도 버리지 않고 최상위 supporting을 승격합니다 (그레이딩 오판 안전장치).

🔍 crag_rewrite — CRAG 질의 재작성 (사이클 1회)

근거를 찾지 못했을 때 질문을 다르게 써서 다시 검색합니다. crag_budget를 0으로 소진하여 최대 1회만 실행됩니다. 이것이 서브그래프의 유일한 사이클입니다.

🔍 answer_node — 답변 생성

등급 통과 페이지(budgeted_pages)를 컨텍스트로 LLM에 답변 생성을 요청합니다.

  • text 경로: 페이지 텍스트 기반 답변 (answer_text_from_pages_x)
  • vision 경로: 1순위 페이지가 figure(표/도표)이면 이미지 직접 분석 (answer_vision_from_page)
🔍 verify_node — 근거 정합성 검증

생성된 답변이 근거와 일치하는지 검증합니다:

  • unsupported_claims — 근거에 없는 숫자/코드가 답변에 있는가?
  • abstain — "확인할 수 없습니다" 류의 회피 답변인가?
  • transcription_ocr_mismatch — vision 경로에서 전사와 OCR이 불일치하는가?
🔍 rollback A/B/C — 롤백 복구 전략
롤백트리거전략
A: rollback_top1text 회피 + top ≥ 0.5등급 통과 1순위 페이지만으로 재생성
B: rollback_vision숫자 미지원 + 스캔본text → vision 교차확인
C: rollback_ocr전사 ≠ OCRvision → 텍스트 재구성

각 롤백은 단발 실행 후 finalize로 빠집니다 (루프 없음).

🔍 finalize — 결과 정리 및 출력

근거 해석, 이미지 사본, 메트릭 정규화를 수행하고 result dict를 생성합니다. 이 dict가 메인그래프의 rag_result로 전달됩니다.

프롬프트 템플릿 시스템

PromptLoader는 prompts/*.md 파일을 string.Template으로 로드합니다.

  • 핫리로드: 파일의 mtime을 캐시하여, 파일이 바뀌면 서버 재시작 없이 즉시 반영
  • 안전 치환: safe_substitute()를 사용하여 누락 변수는 원문($var)으로 남김
  • 주석 제거: <!-- ... --> 형태의 HTML 주석은 렌더 시 자동 제거

🖥️ 프론트엔드 (웹 UI) SPA

프론트엔드는 static/ 폴더에 있는 단일 페이지 애플리케이션(SPA)입니다:

  • index.html — 기본 HTML 구조
  • styles.css — 채팅 UI 스타일
  • app.js — 채팅 로직, SSE 처리, 버튼/되묻기 렌더링

주요 기능

  • SSE 스트리밍: /api/chat/stream에 접속하여 실시간 진행상황 표시
  • 시나리오 버튼: 서버에서 받은 options 배열을 동적 버튼으로 렌더링
  • 되묻기 UI: clarify 이벤트 수신 시 후보 선택 버튼 표시
  • 근거 이미지: evidence[].image_url을 클릭 가능한 이미지로 렌더링
  • 경고 배너: warnings 배열을 경고 박스로 표시
  • 피드백: 👍/👎 버튼 → /api/feedback → LangSmith 기록

📱 모바일 앱 (Flutter) Cross-Platform

mobile_app/은 Flutter(Dart)로 만든 크로스플랫폼 모바일 클라이언트입니다.

mobile_app/ ├── lib/ │ ├── main.dart # 앱 진입점 │ ├── config/ # API URL 등 설정 │ ├── models/ # 데이터 모델 │ ├── screens/ # 화면 위젯 │ ├── services/ # API 호출 서비스 │ └── widgets/ # 재사용 위젯 ├── android/ ├── ios/ └── pubspec.yaml

백엔드 연동

모바일 앱은 chatbot_demo_v2의 REST API(/api/chat, /api/chat/stream 등)를 HTTP로 호출합니다. 현재 config/에 API URL이 하드코딩되어 있어, Docker 통합 시 환경변수로 교체해야 합니다.

🐳 Docker 통합 및 독립 프로토타입 가이드 최종 목표

🎯 통합 전략 개요

현재 chatbot_demo_v2(백엔드)와 mobile_app(프론트)가 분리되어 있습니다. Docker Compose로 통합하여 단일 명령(docker compose up)으로 전체 시스템을 실행하는 것이 목표입니다.

서비스역할이미지 베이스포트

Step 2: 주요 고려사항

🔑 API 키 관리

  • GEMINI_API_KEY는 Docker Compose의 env_file 또는 secrets로 주입
  • 이미지에 API 키를 포함하지 말 것
  • 웹검색 전용 키(WEB_SEARCH_GEMINI_API_KEY)가 별도면 분리 주입

📁 볼륨 마운트

  • ragcore/ — Vendored RAG 엔진 (빌드 시 COPY)
  • data/ — FAQ/시나리오/임베딩 (빌드 시 COPY)
  • ragdata/ — 인덱스/파싱 캐시 (볼륨 마운트)
  • runtime/evidence/ — 근거 이미지 사본 (볼륨 마운트)

🌐 네트워크

  • Ollama는 내부 네트워크에서만 접근
  • backend → ollama는 http://ollama:11434로 통신
  • mobile-web → backend는 http://backend:8002로 통신
  • 외부 노출: mobile-web의 80번 포트만

⚙️ ragcore 경로 조정

  • RAGCORE_ROOT를 컨테이너 내부 경로로 설정
  • RAGCORE_CONFIG의 config.yaml 내부 경로도 조정
  • sys.path 삽입이 컨테이너 환경에서 동작하는지 확인

Step 3: Dockerfile 예시 (Backend)

# chatbot_demo_v2/Dockerfile
FROM python:3.11-slim

WORKDIR /app

# 시스템 패키지 (빌드 도구, OCR 등)
RUN apt-get update && apt-get install -y --no-install-recommends \
    build-essential git && rm -rf /var/lib/apt/lists/*

# Python 의존성
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 앱 코드 + vendored ragcore + 데이터
COPY . .

# 환경변수 기본값
ENV RAGCORE_ROOT=/app/ragcore
ENV RAGCORE_CONFIG=/app/ragcore/rag3/config.yaml
ENV DEMO_PORT=8002
ENV DEMO_DATA_DIR=/app/data
ENV DEMO_STATIC_DIR=/app/static
ENV PROMPTS_DIR=/app/prompts

EXPOSE 8002

CMD ["python", "-m", "chatbot_demo_v2"]
