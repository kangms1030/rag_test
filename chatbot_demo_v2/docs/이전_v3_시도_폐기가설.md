정답 FAQ 는 여전히 1위인데, **경쟁 FAQ 의 변형이 같이 올라와** 1·2위 차가 사라진다.
이 매처의 핵심 판별자는 best 가 아니라 **margin** 이라 되묻기로 샌다.

**임계 재산출로도 못 살린다.** 증강 색인 캘리브레이션 결과 `hard_negative` 중앙값 **0.9954** —
양성 분포와 음성 분포가 완전히 겹쳐 **쓸 수 있는 임계가 존재하지 않았다.** 색인 자체의 변별력이 파괴된 것이다.

**무엇이 문제였나**: 모델이 만든 변형이 **일반적 표현으로 수렴**한다("학교 인터넷 회선이 …").
그런 문장은 여러 FAQ 에 똑같이 잘 맞아 회수는 늘지만 변별이 죽는다.
대조: 골든셋에서 사람이 쓴 패러프레이즈 8개는 **앵커 용어를 남겼고**(스쿨넷·CAT.5e·ping·WEISS) 라우팅이 정상이었다.

> **다시 시도한다면**: 앵커 보존형 프롬프트("무엇에 대한 질문인지 특정하는 단어는 반드시 남길 것")로만.
> 그냥 "패러프레이즈 생성해줘"는 이미 실패했다.

- **`sum_topk` 은 긴 표 페이지를 밀어 올린다.** 셀 파편이 여러 청크로 흩어져 합계가 커진다. v2 가 `max` 를 쓴 게 맞았다.

  ```
  OFF: 통합 · 관제 / 무선 · 공유 / 학내 · 망 / 선 · 번 · 장
  ON : 통합관제      / 무선공유기 / 학내망   / 선번장
  ```

  리랭크 점수가 달라진 문항 **3/80**. 이유는 구조다 — BM25 는 RRF 에 **순위로만** 기여하고,
  후보 20개를 실제로 정하는 것은 dense 이며, 최종 순서는 크로스인코더가 다시 매긴다.
  **코퍼스가 커져 dense 변별력이 떨어지기 전엔 지렛대가 아니다.**
- **`heading_path` 는 값이 있어도 못 믿는다.** 청크 2,423/2,424 개에 값이 있지만
  코퍼스의 54%가 스캔·표라 MinerU heading 이 부정확하고, 잘못된 섹션 경계가 정답 문장을 잘라낸다.
- **RRF 가중치는 이 규모에서 지렛대가 아니다.**

## 3. 방법론 교훈 (설계보다 이게 더 오래 간다)

1. **"실패 원인이 특정됐다"는 것이 "그 처방이 듣는다"는 뜻은 아니다.**
   `faq_para_02` 의 0.027점은 진짜 원인이었지만, 처방이 **다른 17문항을 망가뜨렸다.**
2. **여러 지표가 한 방향으로 크게 무너지면 가설이 아니라 측정 경로를 먼저 의심하라.**
   Phase 3 판정이 "라우트 82.7→48.1%"로 나왔을 때 원인은 프롬프트가 아니라 **스트리밍 인코딩 버그**였다
   (`iter_lines(decode_unicode=True)` 가 SSE 에 charset 이 없어 ISO-8859-1 로 디코드 → 한글 52문항 중 38개 손상).
   깨진 답변은 조용히 실패하지 않는다 — `must_include` 불일치 → grader 미해결 → RAG 재시도 →
   롤백 0→11 · 지연 3.6배. **답변 본문을 눈으로 한 번 보는 것이 지표 20개보다 빨랐다.**
3. **A/B 도중에 코드를 고치지 마라.** 한 번 그래서 4개 설정 중 2개를 다시 돌렸다(44콜 추가 소모).
   "한 번에 한 항목만"은 **설정만이 아니라 코드에도 적용된다.** 프롬프트는 핫리로드라 특히 위험하다.
4. **429 가 나면 그 실행은 버려라.** 로컬 폴백된 문항이 지표를 오염시킨다.
   그리고 429 의 정체를 확인하라 — RPM 이 아니라 **월 지출 상한**일 수 있다.
5. **"무관 텍스트를 빼면 근거 정밀도가 오른다"는 산술이 성립하지 않는다.**
   승격 단위를 줄이면 정답 페이지도 같이 줄어 분자·분모가 함께 감소한다.
6. **비용 추정이 크게 빗나갔다.** e2e 1회 = Gemini **169콜**(예상 70콜의 2.4배).
   로컬 12b 오프라인 배치는 **39초/건 = 2,424건에 26시간**(예상 3시간의 9배).
