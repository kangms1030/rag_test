## 3. 계획서에서 의도적으로 벗어난 4곳 (근거 포함)

| 계획 | 실제 | 이유 |
|---|---|---|
| LLM 노드(contextualize/compose/grader)에 `RetryPolicy` | **RAG 서브그래프의 `retrieve`/`answer_node`/`verify_node`에만** 적용 | `LlmHelper.chat()` 이 예외를 삼키고 `None` 을 반환(→pass-through)해 재시도가 애초에 발동하지 않음. 형식적 no-op 대신 실제 외부 호출 노드에 적용 |
| rag 래퍼 노드에 LangGraph `CachePolicy(ttl=…)` | 어댑터 내부 **수동 TTL 캐시**(`SubgraphRagAdapter`) | `CachePolicy` 는 노드 입력 상태로 키를 만드는데 `ChatState` 에는 매 턴 달라지는 값(session_id·messages·타임스탬프)이 있어 캐시가 절대 적중하지 않음. 또한 **락 획득 전** 캐시를 확인해야 다른 질문 처리 중에도 429 없이 즉답 가능 (계획서가 허용한 대체안) |
| grader 를 모든 경로에 적용 | **FAQ 경로만** 판정, RAG 경로는 생략 | RAG 는 rag3x 내부 `verify` 가 이미 근거 정합성을 판정 — 중복 LLM 호출 1회 절약(계획서 §11-5 지침) |
| 서브그래프를 `add_node(subgraph)` 로 삽입 | **래퍼 노드 함수**로 삽입 | 부모(`ChatState`)와 자식(`RagState`) 스키마가 달라 직접 삽입 불가. LangSmith 에는 동일하게 child run 트리로 기록됨(실측 확인) |

그 외 `decompose`(S0)·`fail_fast`(P1a)는 계획대로 **생략**했습니다(기본 플래그 OFF이며 등가성 기준도 OFF).

프로젝트 `school-network-chatbot-demo-v2`, 같은 세션의 연속 2턴. 상세 해설과 그림은
[docs/파이프라인_비교.md §4](docs/파이프라인_비교.md) 에 있습니다.

| 확인 항목 | 결과 |
|---|---|
| 사이클 발동 | 턴1에서 `retrieve → crag_rewrite → retrieve` — 예산 소진 후 정지(무한루프 아님) ✅ |
| 대화 메모리 | 턴2의 "나는 대구 고등학교 선생님이야" 가 이전 턴과 합쳐져 **"…갤럭시 기기의 인터넷 속도가 느린 문제에 대해 어디로 문의해야 하나요?"** 로 재작성 ✅ |
| RAG 내부 관측 | v1의 블랙박스 1개가 `prepare/retrieve/crag/answer/verify/finalize` 로 분해되어 기록 ✅ |
| 답변 합성 | `composed=true`(891자), `composer_fallback` 없음, `unsupported_claims=[]` ✅ |
| 정직한 보류 | 턴1은 코퍼스에 근거가 없어 abstain(리랭크 0.063 < floor 0.1) — 설계대로 ✅ |

### 트레이스에서 발견해 **이번에 반영한 것**
1. **서브그래프 child run 이름이 `LangGraph` 로 찍혔다** → `compile(name="rag_subgraph")` 명시
   (`graph/builder.py`). 이제 트레이스에서 어떤 서브그래프인지 바로 식별됩니다.
2. **첫 질문의 38.25s 중 약 31초가 엔진 콜드 초기화**였다 → 시연 절차에 `POST /api/warmup`
   선행을 체크리스트로 명시(README §12).

### 발견했으나 **고치지 않은 것**(근거 있음)
- 턴2의 `verify_node` **64.16s**(전체의 86%). 해당 턴의 Gemini 호출은 답변 1 + 검증 1뿐이고
  답변은 1.19s 였으므로, 검증 1회가 429 백오프에 걸린 것으로 보입니다. **그래프 구조가 아니라
  외부 API 지연**이라 코드를 바꾸지 않았습니다. rag3x 에 `x_conditional_verify_skip` 이 있으나
  발동 하한이 `x_verify_skip_tau=0.6` 이라 이 질의(0.114)에는 해당하지 않습니다.

## 6. 구현 중 발견하고 고친 것 (기록)

1. **composer 환각 가드의 오탐** — `composer_rag.md` 가 "지원센터(1899-0979) 안내"를 지시하는데
   모델이 이를 따르자 `1899`/`0979` 가 "근거 밖 수치"로 판정돼 **정상 합성이 전부 폐기**됐다.
   → 검증 컨텍스트에 **프롬프트 원본 템플릿**(치환 전, 사용자 입력 미포함)을 포함해 교정.
   회귀 테스트: `test_composer_allows_numbers_from_prompt_boilerplate`.
2. **테스트가 실제 Gemini를 호출하고 있었다** — clarify HTTP 테스트가 68초 걸리고 grader가
   진짜 판정을 내려 결과가 흔들렸다. → 모든 테스트에 `OfflineLlm` 주입(2.6초로 복구).
   **새 테스트를 쓸 때 `build_context(..., llm=...)` 주입을 빠뜨리면 같은 문제가 재발합니다.**
3. **`"UNRESOLVED"` 가 `"RESOLVED"` 를 포함** → grader 파싱은 반드시 UNRESOLVED 를 먼저 검사.
4. **에스컬레이션 시 FAQ 판정이 지워졌다** — grader 를 건너뛸 때 `grader_verdict: None` 을
   반환하면 직전 판정이 덮인다. → 건너뛸 때는 `{"_escalate": False}` 만 반환.
5. **FAQ 문서명 포함매칭의 동점 처리 누락** — 같은 길이로 두 문서에 걸리면 먼저 찾은 것을
   집었다(오매칭). → 포함·유사 매칭 **모두 동점이면 거절**로 수정(테스트가 먼저 잡아냄).
6. **FAQ 근거 커버리지의 진짜 원인은 코퍼스가 아니라 인용 방식**(§2 재조사).
   코퍼스에 없는 4종의 참조 94건도 **전부 쪽번호가 없어**, 추가 색인해도 근거 이미지는 늘지 않는다.

## 7. 아키텍처 메모 (다시 손댈 때 재파악 불필요)

1. **패키지 `chatbot_demo_v2`**, `graph/` 는 `app/` 의 형제(최상위) → 임포트 깊이 주의.
2. **ragcore 임포트**: `prepare_ragcore_imports(settings)` 가 `sys.path.insert` + GEMINI 키 통과.
   rag3 모듈은 **함수 안에서 지연 import**(모듈 로드 시점엔 sys.path 미설정).
3. **소형 LLM 백엔드 분리**: `LlmHelper` 가 채팅 전용 백엔드를 별도 지연생성(리랭커·인덱스 미로드)
   → FAQ 경로는 GPU 없이 동작. `GeminiBackend` 는 클래스변수로 rate-limit 을 공유.
4. **metrics**: `rag3.metrics` 는 contextvar → 서브그래프 노드마다 `with metrics.run_metrics(m)` 래핑.
5. **스트림 writer 는 서브그래프로 전파되지 않는다** → 부모 노드(`rag3x_answer`)가 writer 를 잡아
   `adapter.ask(progress=...)` 콜백으로 넘기고, 어댑터가 `deps.scratch["progress"]` 에 보관.
6. **캐시는 락 획득 전 확인** — 다른 질문 처리 중에도 캐시된 답변은 429 없이 즉시 반환.
7. **IDE 진단 거짓양성**: VSCode 가 시스템 Python311 을 봐서 langgraph/rag3 를 "없다"고 표시. 무시.
8. **Windows/Bash**: Bash 툴의 `$(pwd)` 는 MSYS 경로라 네이티브 Python 이 못 읽는다 →
   스크립트는 `Path(__file__)` 기준. 네이티브 curl 은 `/tmp` 를 못 쓴다 → httpx 로 스모크.
   콘솔 한글 깨짐은 cp949 표시 문제일 뿐이며 `-X utf8` 을 붙이면 해결된다.

## 8. 남은 선택지 (모두 선택 사항, 사용자 결정 필요)

| 후보 | 기대 효과 | 판단 |
|---|---|---|
| 코퍼스 갭 문서 증분 색인(`add_doc.py`) | RAG **검색 대상** 확대 | 근거 이미지는 늘지 않음(§6-6). 원본은 `데이터 카탈로그/` 에 존재 |
